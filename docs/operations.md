# 部署、运行与排查

本文面向实际使用和现场排障。功能和双机操作见 [README](../README.md)，设计约束见 [architecture.md](architecture.md)。

## 1. 部署模型

FlashDrop 是**普通桌面进程**，不需要服务端、数据库或云端：

- 每台电脑各自运行一份 `python -m flashdrop`。
- WebUI 仅监听 `127.0.0.1`；通过浏览器操作本机进程。
- 发送端在局域网监听 P2P 控制端口和数据端口。
- 文件只在两台电脑之间流动。

可以从源码运行，也可以：

```powershell
python -m pip install .
flashdrop
```

项目无第三方依赖。构建发行物时确认 `flashdrop/web/*` 静态资源被打包。

## 2. 防火墙与网络

### 2.1 Windows

第一次点击「开启传输」时，Windows Defender 防火墙通常会弹出 Python 的网络访问提示。勾选**专用网络**并允许即可。若之前误点了取消：

1. 打开「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」。
2. 允许运行 FlashDrop 的 `python.exe` 访问专用网络。
3. 或在管理员 PowerShell 中按程序放行：

```powershell
$python = (Get-Command python).Source
New-NetFirewallRule `
  -DisplayName "FlashDrop (Python)" `
  -Direction Inbound `
  -Program $python `
  -Action Allow `
  -Profile Private
```

数据端口是动态选择的，因此**按程序放行**比逐个放行端口更可靠。控制端口固定时也可以额外放行 TCP 控制端口。

### 2.2 两台电脑的连通性

- 两台电脑应连接到同一个局域网/子网。
- 先用 `ping <发送方IP>` 验证基础连通。
- 公司网络、访客 Wi-Fi 或 VLAN 可能禁止客户端互访；此时即使 IP/ping 正确也无法连接。
- VPN 可能改变路由和首选地址。发送端会列出多张网卡的 IPv4；试另一个。
- 虚拟网卡（WSL、Hyper-V、Docker、VMware、Tailscale 等）地址可能出现在列表中，但对方不一定能访问。

### 2.3 端口

| 端口 | 默认 | 绑定 | 使用方 |
|---|---|---|---|
| WebUI | 8765 | `127.0.0.1` | 本机浏览器 |
| 控制/信息 | 45870 | `0.0.0.0` | 接收方连接 |
| 数据 | 发送端自动选择 1–8 个 | `0.0.0.0` | 接收方连接 |

发送端 UI 会显示实际控制端口和数据端口。控制端口填 `0` 时由系统分配；数据端口由发送端从控制端口之后的空闲端口开始扫描，因此可能不是严格连续。

## 3. 运行与生命周期

```powershell
# 开发/日常运行
python -m flashdrop

# 不自动打开浏览器
python -m flashdrop --no-browser

# 指定 WebUI 端口（被占用则自动换）
python -m flashdrop --port 9000

# 输出 debug 日志
python -m flashdrop --debug
```

- 控制台窗口必须保持打开；关闭窗口或终止 Python 进程会停止后端。
- 关闭浏览器标签页**不会**停止传输；重新打开同一 WebUI 地址可以恢复查看。
- `Ctrl+C` 会先尽量通知对端并停止服务。
- WebUI 进程没有系统托盘/开机自启；需要时使用 Windows 任务计划程序或快捷方式自行管理。
- 同一台电脑同时运行多个实例时，需要给每个实例不同的 WebUI 端口；发送端控制端口也不能冲突。

## 4. 断点续传操作

### 4.1 中断后继续

1. 保持接收端保存目录不变。
2. 重新启动/重置接收端，连接同一个发送端（文件清单必须相同）。
3. 选择**同一个保存文件夹**。
4. 检查「可续传」提示，点击「开始接收」。

程序会按文件 ID、路径、大小、mtime 和快速指纹匹配，只接收剩余字节。

### 4.2 放弃续传

在确认没有传输在运行时，可以删除保存目录下的 `.flashdrop`：

```powershell
Remove-Item -Recurse -Force "D:\目标目录\.flashdrop"
```

这会丢弃未完成分片和续传记录，但不会影响已经出现在最终路径中的文件。之后重新接收会从头开始，并可能覆盖同名最终文件。

### 4.3 只清理某个文件

`.flashdrop/state/<file-id>.json` 和 `.flashdrop/parts/<file-id>.part` 是一对。删除两者即可让该文件下次从头接收。不要只删除 state 或只删除 part，两边的匹配会让程序自动忽略孤儿文件，但会浪费空间。

### 4.4 不要删除正在使用的目录

传输进行中不要移动/清理保存目录或 `.part`，这会导致中断。若必须停止，先在 UI 停止/取消，等状态变为错误/取消后再操作。

## 5. 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 接收端“连接发送方失败” | 地址/端口错误；发送端未开启；防火墙；不同子网 | 核对 UI 上实际的控制端口和地址；`ping`；换地址；放行 Python |
| 控制连接成功但数据连接全部失败 | 防火墙/安全软件仅放行控制端口；数据端口被拦截 | 按程序放行 Python；查看发送端 UI 的数据端口；临时关闭安全软件测试 |
| 一直停在“正在建立并行数据通道” | 数据端口连接超时；网络 ACL | 30 秒后应超时；检查双方防火墙和发送端数据端口 |
| 端口被占用 | 上次进程未退出、其他程序占用、UI 端口冲突 | 关闭旧进程；发送端换控制端口或填 0；UI 自动换端口 |
| 点击开始接收提示空间不足 | 剩余空间小于剩余字节 | 释放空间或换目录；续传只计算剩余字节，但仍需覆盖最终文件的空间 |
| 源文件变化导致中断 | 编辑/覆盖了正在发送的文件 | 不要修改发送中的文件；关闭编辑器后重试 |
| 接收完成但目标文件不存在 | 最终化失败 | 看 UI 错误；检查目标是否被占用/只读、路径过长、保留的 `.flashdrop` 分片 |
| 文件名/目录在 Windows 上创建失败 | 非法字符、保留设备名、路径超过 260 字符、磁盘格式限制 | 重新命名源文件/缩短目录层级；当前版本不自动转换 |
| 大量文件启动很慢 | 开始前读取每个文件的快速指纹 | 正常现象；可先打包成压缩文件；UI 会显示准备状态 |
| 传输速度低于预期 | 单盘、Wi-Fi、杀毒扫描、CPU 弱、连接数不匹配 | 用 4–8 条通道；优先有线；检查磁盘占用；避免同时传大量小文件 |
| 浏览器刷新后好像“丢失”了 | 后端仍在，但页面重新拉取状态 | 等状态轮询；检查控制台服务是否仍在运行 |

## 6. 性能与规模

- 默认 4 条数据连接适合多数千兆/2.5G 局域网；UI 可选 1–8。
- 读源文件、写目标盘、SHA/CRC 计算和防火墙检查都可能成为瓶颈；连接数不是越多越好。
- 大文件优于海量小文件：每个文件都要建立 manifest、状态文件、最终化和目录操作。
- 发送前快速指纹会读取每个文件头尾最多 128 KiB；数十万小文件时启动阶段会明显变长。
- WebUI 文件列表分页，但 manifest 一次性放入 welcome 控制帧，硬上限 128 MiB。十万级以上文件建议先打包。
- 接收端允许的数据端口少于请求数是正常降级，不能为 0。
- 进度条速度是平均值（从开始到当前），不是瞬时滑动窗口；网络抖动时会有滞后。

## 7. 安全边界

- **无 TLS、无认证、无访问控制、无加密。**
- 控制端口绑定所有 IPv4 接口；局域网内任何能连上该端口的客户端都可能：
  - 看到文件清单和总大小；
  - 作为接收方开始接收发送端选中的文件；
  - 向发送端提供自己的续传 offset（协议会做范围校验，但不认证）。
- 不要将控制端口或数据端口映射到公网，不要在不可信 Wi-Fi 使用。
- 需要跨公网/零信任传输时，在外层用 VPN（WireGuard/Tailscale 等），或升级为带 TLS+身份认证的版本。
- WebUI 只监听本机回环，但本机其他用户/程序仍可能访问该端口；在共享电脑上注意这一点。

## 8. 升级与数据兼容

- 升级程序不会删除已有的 `.flashdrop` 续传数据。
- 若协议/指纹算法变更，旧状态可能被安全忽略并从 0 开始；这不会损坏最终文件，但会失去续传。
- 升级前先完成或取消正在进行的传输，关闭进程，再替换代码/安装包。
- 跨大版本恢复前，建议先在一个小目录验证一次续传。

## 9. 日志与诊断

- `--debug` 打开模块级 debug 日志；HTTP 请求日志会进入控制台。
- 重要事件：发送端就绪和端口、连接/断开、接收完成、错误。
- 如果程序异常退出，先保留控制台输出；传输数据在 `.flashdrop` 中仍可续传。
- 复现问题时记录：双方操作系统版本、Python 版本、控制端口/数据端口、防火墙状态、网络类型（有线/Wi-Fi/VPN）、文件数量与典型大小、错误文案。

## 10. 恢复建议

1. **先停 UI 操作**：发送端停止，接收端取消，避免继续写。
2. **保留 `.flashdrop`**：这是续传依据；不要为了“清理”先删除。
3. **检查磁盘空间**和最终目录权限。
4. **重新连接**并选择同一目录；若续传记录匹配，UI 会显示可跳过字节。
5. 若失败的最终化文件仍占用/只读，先关闭占用程序，再重试。
6. 只有在确认放弃续传后，才删除对应 state/part 或整个 `.flashdrop`。
