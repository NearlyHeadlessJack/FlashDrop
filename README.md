# 闪传 FlashDrop

**局域网点对点文件快传。** 在两台电脑之间直接开一条多通道、可续传的传输线路，不经过云盘，也不需要外部依赖。

- 收发二合一：启动后选择「我要发送」或「我要接收」。
- 原生文件选择器：直接发送本机文件，不经过浏览器的上传缓冲。
- 多端口并行：1 个信息/控制端口 + 1–8 条独立数据通道。
- 断点续传：中断后重新连接并选择同一个保存文件夹，自动跳过已经写入的字节。
- 块级校验：每个数据块 CRC32 校验；文件完整落盘后才原子替换到目标路径。
- 本地 WebUI：文件预览、增删、连接确认、实时进度都在浏览器中完成。
- 只依赖 Python 标准库，支持 Windows / Linux / macOS（原生选择窗口需要 Tk）。

> **安全边界**：当前版本不提供加密、身份认证或访问控制。请只在自己信任的局域网中使用，不要把控制端口暴露到公网。

## 快速开始

要求 Python **3.10+**，Windows 安装包默认自带 `tkinter`。项目不需要 `pip install` 任何第三方包。

```powershell
cd C:\Users\jack\flash
python -m flashdrop
```

浏览器会自动打开本地控制台。也可以直接双击 [`start.bat`](start.bat)。

常用参数：

```powershell
python -m flashdrop --no-browser          # 不自动打开浏览器
python -m flashdrop --port 8765           # 指定 WebUI 端口（被占用时自动换端口）
python -m flashdrop --debug               # 输出调试日志
python -m flashdrop --version
```

WebUI 只监听 `127.0.0.1`，是控制台，不是传输端口。传输使用独立的控制端口和数据端口。

## 两台电脑怎么用

### 1. 发送端

1. 选择「我要发送」。
2. 用系统窗口选择文件/文件夹，或点「手动输入路径」粘贴路径。
3. 检查文件清单，可删除、继续添加，直到点击「开启传输」。
4. 在「传输设置」中确认控制端口和并行通道数。控制端口填 `0` 会由系统自动分配。
5. 点击「开启传输」。页面会显示：
   - 接收方需要填写的 **本机 IP**
   - **信息传输端口**（控制端口）
   - 数据端口数量和具体端口
6. 把首选地址或 `IP:端口` 告诉接收方。点击地址旁的「复制地址」即可。

发送端在对方确认保存位置之前不会发送文件。对方连接后，发送端显示「等待对方确认保存位置」；对方点击「开始接收」才进入真正的数据传输。

### 2. 接收端

1. 选择「我要接收」。
2. 填写发送端显示的主机 IP 和控制端口。也可以直接把发送端复制的 `IP:端口` 粘贴进主机地址栏，程序会自动拆分。
3. 点击「尝试连接」。此时只交换文件清单，不会立即传输。
4. 查看文件名、数量和总大小。
5. 选择本机保存文件夹，或手动输入路径后点「应用路径」。
6. 点击「开始接收」。接收端会打开多条数据连接，并逐块校验写入。

已有可续传分片时，保存位置下方会显示「发现 N 个可续传文件」。开始后进度条会从已保存的百分比继续。

## 断点续传

接收端在保存目录下维护一个隐藏目录：

```text
<你选择的保存文件夹>/
├── .flashdrop/
│   ├── state/<file-id>.json   # 来源路径、大小、mtime、快速指纹、状态
│   └── parts/<file-id>.part   # 连续写入的临时分片
└── ...最终文件...
```

- 只有路径、大小、修改时间和快速指纹全部匹配时，旧分片才会被复用。
- 分片按连续顺序写入；崩溃或断线后，文件长度就是可安全续传的字节数。
- 每个文件完成后使用同卷 `os.replace` 原子替换到最终路径，并恢复源文件的修改时间。
- 整次传输成功后清理对应 `.flashdrop` 记录；失败时保留，便于下一次续传。
- 重新连接时必须选择**同一个保存文件夹**。删除 `.flashdrop` 会失去续传能力，但不会影响已经落盘的最终文件。

## 可靠性设计

- **TCP**：数据通道使用 TCP，控制与数据流分离。
- **帧边界**：控制消息是 4 字节大端长度前缀 + UTF-8 JSON；数据帧是固定 36 字节头 + 原始字节。
- **块校验**：每个数据块附 CRC32，接收端逐块验证后再写入。
- **大小校验**：每个文件写满预期大小，且无乱序残留后才允许保存。
- **原子落盘**：先写 `.part`，`fsync` 后 `os.replace`；不会把半成品暴露成最终文件。
- **源文件复查**：发送开始前生成快速指纹；传输结束后再次核对源文件的大小与 mtime，发现中途修改就让本轮失败，而不是确认成功。
- **并行窗口**：发送端限制同时在途的块数量，避免某条连接变慢时接收端无界缓存。
- **心跳**：控制连接每 5 秒心跳，失联会中止本轮并保留分片。

### 指纹说明

为了在巨大文件上快速开始，当前指纹采样文件头、尾部各最多 64 KiB，并混入大小与 `mtime_ns`。它能可靠识别普通编辑和截断，但**不是全文件加密哈希**。传输完整性由“每块 CRC32 + 精确字节数 + 最终原子写入”保证；若需要抵御恶意篡改或极端随机碰撞，应升级为全文件哈希校验。

## 端口和防火墙

| 用途 | 默认 | 说明 |
|---|---|---|
| WebUI | `127.0.0.1:8765` | 只在本机可访问，被占用时自动换端口 |
| 信息传输 | `0.0.0.0:45870` | 发送端监听，接收方填写这个端口 |
| 数据通道 | 控制端口之后的空闲端口 | 默认 4 条，1–8 可配置；具体端口由控制消息告知对方 |

Windows 第一次监听时通常会弹出防火墙提示。请允许 Python 访问**专用网络**，或者按程序路径放行。更稳妥的做法是允许 `python.exe`，而不是逐个放行临时数据端口。

如果发送端有多张网卡，页面会列出全部本机 IPv4 地址。首选地址可能是虚拟网卡/WSL/VPN；对方连不上时换一个地址即可。

## 常见问题

| 现象 | 处理 |
|---|---|
| 接收端连接超时 | 两台电脑是否在同一局域网；发送端是否已经点「开启传输」；防火墙是否放行；尝试发送端列出的其他 IP |
| 控制端口被占用 | 在发送端修改控制端口，或填 `0` 自动分配 |
| 数据连接建立失败 | 防火墙可能只放行了控制端口；按程序放行 Python，或检查安全软件 |
| 系统选择窗口没出现 | 使用「手动输入路径」；Linux 上可安装 `python3-tk`；在远程桌面/无桌面环境使用手动路径 |
| 点「开始接收」提示空间不足 | 选择空间更大的目录；续传时会按剩余字节数检查 |
| 传输到一半中断 | 重新连接并选择同一保存目录，程序会扫描 `.flashdrop` 续传 |
| 接收完成但文件没出现 | 检查是否有保存失败提示；部分成功时已保存文件会保留，失败文件的 `.flashdrop` 记录也会保留 |
| 文件名在 Windows 上非法或路径过长 | 当前版本不主动重命名；请缩短路径或在源端调整文件名 |

## 项目结构

```text
flashdrop/
├── cli.py            # 启动参数、浏览器打开、生命周期
├── app.py            # 应用门面与 API 业务方法
├── web.py            # 仅本机的 HTTP/JSON 服务
├── catalog.py        # 文件选择、目录展开、清单指纹
├── protocol.py       # 控制帧、数据帧、路径安全校验
├── control.py        # 带心跳的 JSON 控制通道
├── sender.py         # 监听、会话状态机、多通道发送调度
├── receiver.py       # 连接、清单、分片写入、续传与落盘
├── picker.py         # 独立进程中的 Tk 原生选择窗口
├── metrics.py        # 进度、速度、ETA
├── netutil.py        # 端口分配、地址发现、Socket 选项
└── web/              # 无构建步骤的 HTML/CSS/JS WebUI
tests/                # unittest + 本机双实例端到端测试
docs/                 # 架构、协议、开发、运维与决策文档
```

## 当前版本的限制

- v0.1.0 **无加密、无认证**，仅适合可信局域网。
- 单进程一次只服务一个发送或一个接收会话。
- 不传输空目录、符号链接目录、ACL/权限位；会保留普通文件和目录结构，并恢复 mtime。
- 不支持传输中动态增删文件；开始发送后清单固定。
- 目标文件会被覆盖；同名冲突会在发送端自动加 ` (2)` 后缀，请在预览中确认传输路径。
- 超多文件（十万级）时，清单需整体放入控制帧，WebUI 列表会分页；建议先分组传输。
- 使用抽样快速指纹，不是完整文件 SHA-256；见上文「指纹说明」。
